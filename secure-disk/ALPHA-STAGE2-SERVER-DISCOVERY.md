# NODEX v0.4.7 — Alpha Stage 2: Server Discovery

## Изменения

- `config.js` хранит выбранный адрес в `localStorage` (`nodex_server_url`) и конфигурацию API/IPFS (`nodex_server_config`).
- Экспортируемые `API_BASE` и `IPFS_API` являются live bindings ES-модуля. После сохранения адреса они обновляются без перезагрузки страницы; `auth.js` и `app.js` получают новые значения через существующие импорты.
- В браузерном режиме без настроек остаются прежние `localhost:3001` и `localhost:5001`.
- В нативном Capacitor-режиме без сохранённого сервера показывается модалка подключения и восстановление авторизации не запускается до выбора хоста.
- В настройках добавлен раздел подключения, ручной ввод адреса, сканирование QR и окно генерации QR для Windows.
- QR создаётся локальной библиотекой `qrcode-generator`, без стороннего QR API.

## Формат QR

```json
{
  "type": "NODEX_HOST",
  "api": "https://192.168.1.5:3001/api/v1",
  "ipfs": "https://192.168.1.5:3001/ipfs/api/v0"
}
```

IPFS URL намеренно указывает на будущий ограниченный прокси NODEX, а не на административный Kubo API. Сам прокси в этом этапе не реализован.

## Транспорт и безопасность

- Для удалённого LAN-хоста требуется HTTPS. HTTP разрешён только для loopback (`localhost`, `127.0.0.1`, `::1`).
- QR не содержит токенов, приватных ключей, VMK или pairing-секретов.
- Сканер повторно проверяет тип QR, схему, путь API и совпадение origin API/IPFS.
- Камера требует secure context и разрешения. При недоступной камере остаётся ручной ввод.
- `qrcode-generator` и `html5-qrcode` пока загружаются из CDN как и в исходной v0.4.7 странице; для автономной упаковки их следует локализовать в следующих этапах.

## Ограничения этапа

1. Windows не определяет все LAN-интерфейсы из браузерного JavaScript. Поле адреса заполняется автоматически только если страница открыта с LAN hostname; для localhost IP вводится вручную. В Electron позже можно передавать адрес из main process.
2. HTTPS-сертификат Windows-хоста и процедура доверия Android ещё не реализованы. До их появления удалённое подключение по LAN не готово к эксплуатации.
3. Backend endpoint `/ipfs/api/v0` пока не реализован. Нельзя заменять его прямым открытием Kubo `:5001`.
4. Сохранение адреса не проверяет доступность сервера; проверка произойдёт при попытке восстановить сессию/авторизоваться.

## Проверки этого этапа

- `node --check`: `config.js`, `auth.js`, `app.js`.
- Тест конфигурации в Node с mock LocalStorage: browser defaults, обновление live bindings, HTTPS для LAN, отказ от HTTP LAN.
- Проверка HTML ID: дубликатов нет; обязательные элементы Server Discovery присутствуют.
- ZIP integrity: проверена после упаковки.

Камера на физическом Android, LAN HTTPS, cookies, backend и IPFS proxy не тестировались.
